# Smart Exchange D-Day 개발 지침

이 문서는 저장소 전체에 적용된다. Codex와 모든 기여자는 코드를 작성, 수정, 검토할 때 아래 원칙을 따라야 한다.

## 프로젝트 목적

Smart Exchange D-Day는 해외여행자를 위한 Python 기반 환전 타이밍 알림 시스템이다.

이 시스템은 미래 환율을 예측하지 않는다. 실제 현재 환율이 최근 과거 데이터의 통계적 기준과 비교하여 상대적으로 낮은 구간인지 탐지하고, 사용자의 여행 출발일과 분할 환전 진행 상황을 고려해 알림을 제공한다.

## 비협상 원칙

- 모든 애플리케이션과 계산 로직은 Python을 기반으로 구현한다.
- 머신러닝, 딥러닝, 생성형 AI 또는 기타 학습 기반 예측 모델을 사용하지 않는다.
- 미래 환율, 환율 방향, 목표 환율 또는 상승·하락 확률을 예측하지 않는다.
- 판단은 과거 및 현재의 관측 데이터에 기반한 결정론적 통계 규칙으로 수행한다.
- "환율이 오를/내릴 것이다"가 아니라 "현재 환율이 최근 통계 분포에서 상대적으로 낮은 구간이다"라는 의미로만 결과를 해석한다.
- 판단 결과에는 사용한 지표, 기준값, 충족한 조건 등 사람이 확인할 수 있는 근거를 남긴다.

## 필수 통계 지표

환전 구간 판단에는 다음 지표를 사용한다.

- 최근 6개월 및 1년 구간의 Percentile Rank
- 60일 Simple Moving Average(SMA 60)
- 120일 Simple Moving Average(SMA 120)
- 현재 환율과 각 이동평균 사이의 이격률
- Bollinger Bands

모든 환율 시계열은 동일한 환율 종류와 출처를 일관되게 사용해야 한다. 비교 전에 환율을 "외화 1단위를 구매하는 데 필요한 KRW" 방향으로 정규화하여 값이 낮을수록 여행자에게 유리하도록 한다.

지표의 기간, 최소 관측치, 결측치 처리, 동률 처리, Bollinger Bands의 기간과 표준편차 배수는 설정 또는 명시적인 정책으로 관리한다. 암묵적인 기본값을 계산 코드 곳곳에 중복 작성하지 않는다.

## D-Day 및 분할 환전 정책

- 알림 threshold는 사용자의 여행 출발일까지 남은 D-Day에 따라 결정한다.
- 출발일까지 시간이 많이 남으면 엄격한 threshold를 적용한다.
- 출발일이 가까워질수록 threshold를 단계적으로 완화한다.
- 통계적으로 유리한 구간을 탐지하는 조건과 출발 전 환전을 완료하기 위한 일정 조건을 구분한다.
- 최종적으로 3~4회의 분할 환전을 유도하며, 이미 완료한 회차와 누적 환전 비율을 판단에 반영한다.
- 동일한 입력 데이터와 동일한 정책 버전은 항상 동일한 판단 결과를 만들어야 한다.
- D-Day 단계, threshold, 회차별 비율 등의 정책값은 코드에 흩어 놓지 말고 중앙 설정 또는 정책 객체에서 관리한다.

## 코드 변경 절차

코드를 변경하기 전에 반드시 기존 동작을 먼저 확인한다.

1. 관련 코드, 설정, 테스트 및 문서를 읽는다.
2. 기존 테스트를 실행하거나, 실행할 수 없다면 현재 동작을 재현 가능한 방식으로 확인한다.
3. 변경이 기존 계산식, 알림 조건, D-Day 정책 및 분할 환전 상태에 미치는 영향을 파악한다.
4. 기존 동작을 의도하지 않게 변경하지 않는 최소 범위로 수정한다.
5. 변경 후 관련 테스트와 전체 테스트를 가능한 범위에서 실행한다.

기존 테스트가 실패하는 상태라면 실패 내용을 기록하고, 이번 변경으로 생긴 실패와 기존 실패를 구분한다. 기존 동작을 알 수 없는 상태에서 계산 규칙을 추측하여 교체하지 않는다.

## 테스트 원칙

- Percentile Rank, SMA 60/120, 이동평균 이격률, Bollinger Bands를 포함한 모든 계산 로직에는 단위 테스트를 작성한다.
- D-Day threshold, 알림 판단 및 3~4회 분할 환전 정책에도 테스트를 작성한다.
- 계산 로직을 추가하거나 수정할 때에는 정상 사례뿐 아니라 경계값, 최소 관측치, 결측치, 오래된 데이터 및 잘못된 통화 방향을 다루는 테스트를 함께 작성한다.
- 버그를 수정할 때에는 가능하면 해당 버그를 재현하는 회귀 테스트를 먼저 추가한다.
- 부동소수점 계산은 명시적인 허용 오차를 사용해 검증한다.
- 테스트를 통과하지 않은 계산 로직을 완료된 변경으로 간주하지 않는다.

## 보안 및 설정

- API key, access token, 비밀번호, 인증서 또는 기타 secret을 소스 코드에 직접 작성하거나 커밋하지 않는다.
- secret은 환경 변수나 승인된 secret 관리 수단으로 주입한다.
- 예제 설정과 테스트 fixture에는 실제 secret이 아닌 명백한 더미 값을 사용한다.
- 로그, 예외 메시지, 테스트 출력에 secret 또는 민감한 사용자 정보를 노출하지 않는다.

## 구현 경계

허용되는 작업:

- 과거 환율 데이터에 대한 기술 통계 계산
- 규칙 기반 점수 또는 명시적 조건식
- 정책 버전별 historical replay 및 backtest
- 데이터 품질 검사, 중복 알림 방지 및 감사 가능한 판단 기록

금지되는 작업:

- 회귀, 분류, 시계열 예측 또는 강화학습 모델 도입
- 모델 학습을 위한 feature engineering 및 학습 파이프라인 구축
- 미래 환율이나 수익률의 추정값·확률·신뢰구간 제공
- 통계적 저평가 탐지를 투자 수익 보장이나 미래 방향 예측으로 표현하는 행위

요구사항이 이 원칙과 충돌하거나 머신러닝·환율 예측 도입을 암시한다면 구현을 진행하기 전에 충돌을 명확히 알리고 사용자 확인을 받아야 한다.
